It starts with what you've already said.

The first run reads 90 days of your Claude Code sessions. Every correction you kept repeating becomes a Reviewer, with your own words kept as its evidence.

  1. “why is this called usr? spell it out”
    →
    Spell out namesBlock abbreviations like usr, cfg, btn. A name says what the value holds.
  2. “never show error.message to the user, map it to copy”
    →
    Errors reach users through the error mapBlock an error's own text reaching a person. Throw a typed code instead.
  3. “stop casting the API response, validate it”
    →
    No type castsBlock as on data nobody checked. Validate it where it comes in.

Examples. Yours come from your own sessions.

What happens on a commit

  1. 1
    Your agent commits.

    A git hook takes the staged change.

  2. 2
    Every rule that applies judges it at once.

    Each Reviewer is its own read-only Claude Code session. The commit waits for the slowest one, not for all of them in a row.

  3. 3
    A broken rule stops the commit.

    The agent gets the file, the lines and the fix, corrects the code and commits again. You hear about it only if you ask.
